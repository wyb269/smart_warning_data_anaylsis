# 防返贫数据展示与智能预警平台

本项目围绕防返贫业务中的多源人员数据，完成了从公司数据仓接入、Hive 数据加工、自动预警计算到平台报表展示的整体建设。仓库提供项目总结和 Pencil 页面原型，便于了解方案、数据链路与页面设计。

## 项目目标

项目把分散在医疗、民政、就业、住房等来源中的人员记录整合为统一的数据视图，让授权工作人员先看清具体数据，再查看自动计算的预警及依据，减少逐人查找、比对和初筛的时间。平台不设置逐人分派、办理状态或人工判断，也不把自动预警等同于正式的防返贫认定。

## 技术路径

```mermaid
flowchart LR
    A[外部授权数据] --> B[公司集中数据仓 / Hive 源表]
    B --> C[人员匹配、标准化、质量检查]
    C --> D[整合人员表与指标结果表]
    D --> E[经确认规则自动计算]
    E --> F[人员、预警、总览、来源状态报表]
    F --> G[授权查询服务]
```

源表保留以供追溯；人员报表、指标结果和预警报表由源表加工生成，并不覆盖源表。平台通过授权查询服务消费报表结果，不从个人电脑直接接入外部部门数据。

## Hive 数据处理方法

数据在公司集中式 Hive 仓库中按“源记录 → 标准明细 → 指标结果 → 页面报表”逐层加工。每层都保留批次、来源和业务时间，既能更新报表，也能从某条预警回查其依据。

| 数据层 | 处理粒度 | Hive 中完成的工作 | 页面用途 |
| --- | --- | --- | --- |
| ODS 源表层 | 来源记录和接入批次 | 保存授权源记录、原始字段、所属期和入仓时间；按批次分区 | 数据追溯与重算 |
| DWD 标准明细层 | 人员或业务事件 | 统一证件字段、行政区、日期和金额格式；匹配人员；去除同一事件的跨批重复 | 形成可靠的人员及事件明细 |
| DWS 指标层 | 人员 × 指标 × 统计期 | 关联医疗、救助、身份等事件；按已确认规则计算基础判断与预警指标，保存结果、支撑值和来源 | 人员详情与预警依据 |
| ADS 报表层 | 人员清单或地区/时间汇总 | 生成清单、详情、预警、区域分布和数据状态视图 | 平台查询与图表展示 |

具体处理步骤：

1. **字段标准化**：用 Hive SQL 的 `CAST` 与 `CASE WHEN` 统一日期、金额、是否类字段；把省、市、县、乡、村分别落到五级地址字段。空值保留为空，不转成“否”或 0。
2. **人员关联**：在授权计算环境内使用受保护的人员匹配键连接各来源。姓名只用于展示，不单独作为连接条件；户主关联没有可靠依据时保持为空。
3. **事件去重**：按“人员键 + 来源事件键”划分重复组，使用 `ROW_NUMBER() OVER (PARTITION BY ... ORDER BY 更新时间 DESC)` 保留最新有效记录；同一事件跨批重新送达时更新证据，不重复计数。
4. **指标计算**：K“人员有效性”和 L“是否农村户籍”作为基础判断；M–V 的十项指标按规则版本、统计窗口和来源有效性逐项计算。医疗自付先以 `SUM` 汇总规定期间的个人金额，再与一万元阈值比较；临时救助按近三个月审批事件判断；“新增”类指标与上一有效基线比较。
5. **结果分层**：每项指标使用 `命中 / 确认未命中 / 无法判断 / 未接入` 四态。只有来源覆盖、人员匹配、数据时效和规则条件都满足时，才允许写“确认未命中”。缺批、字段缺失、来源冲突进入“无法判断”，并保存原因。
6. **批次更新**：加工任务按数据所属期和接入批次增量运行，更新对应分区与报表；规则调整后按版本重算，并保留历史结果与来源批次。

## 数据分析与报表口径

分析重点是**人员覆盖、指标命中和数据可信度**，三类结果分别计算，避免把原始记录条数当成人数：

| 指标 | 计算口径 | 业务解释 |
| --- | --- | --- |
| 已展示人员数 | 授权范围内 `count(distinct person_key)` | 一人多条源记录只算一人 |
| 命中预警人员数 | 至少一项已启用指标命中的人员去重数 | 用于衡量需关注的人群规模 |
| 指标命中次数 | 按“人员 × 指标”累计命中数 | 一人命中三项计三次，不能与命中人数混用 |
| 数据待补人员数 | 存在缺批、未匹配、未接入或无法判断的人员去重数 | 单独展示，不计入“确认未命中” |
| 字段完整率 | 已取得有效值的必需字段数 ÷ 应取得的必需字段数 | 衡量整合表能否支撑详情展示 |
| 来源更新延迟 | 最近可用时间与约定更新时间的差值 | 解释统计结果的时效边界 |

Hive SQL 使用 `GROUP BY` 按地区、指标和数据期汇总，用 `COUNT(DISTINCT person_key)` 统计人数，用“人员 × 指标”结果表统计命中次数，并通过同一人员键分析多指标共现。批次趋势按数据所属期生成，缺批保留缺口，不把缺失画成真实的零。区域比较同时展示来源覆盖和可匹配人数；覆盖不一致时，不用预警绝对数直接给地区排“风险高低”名次。总览数字、人员清单和预警列表共用同一批次与授权筛选条件，确保点击图表后可以追溯到具体人员及指标证据。

## 查询服务与页面展示

Hive 负责批量加工和统计。为满足人员筛选、分页及详情查看的交互需求，报表层的最小必要字段同步到授权的 MySQL 查询库；Java Spring Boot 接口负责身份与数据范围校验、脱敏、统一分页和访问留痕；Vue 3 与 ECharts 展示人员数据、预警结果、区域分布和来源状态。查询库不复制原始部门表，页面不展示内部人员键。

加工任务按数据所属期分区读取，先在 Hive 中完成预汇总，再向查询库同步页面所需的结果，减少交互查询时的跨来源连接和全表扫描。每日检查分区更新、人员匹配率、重复事件数、必需字段完整率和来源延迟；异常批次进入数据状态报表，由运维和数据治理流程处理。

## 核心设计原则

1. **数据展示优先**：人员清单可筛选省、市、县、乡、村，详情逐项展示《整合表》B–V 的必要字段。
2. **预警由规则产生**：仅启用有数据来源且规则已确认的指标，展示具体值、来源、时间和规则版本。
3. **缺失不是未命中**：分别标明已命中、确认未命中、无法判断、未接入；统计不把后两者算作无风险。
4. **权限与脱敏**：仅向授权人员展示最小必要字段，证件号默认脱敏，个人详情访问留痕。
